# Body fields:
#   req            — "add" | "del" (see also: cart-add/no-ref-token.json for the "add" variant without ref_token)
#   item_type      — "a" (album) | "t" (track)
#   item_id        — bandcamp item id
#   band_id        — bandcamp band id
#   unit_price     — minimum or chosen NYP price
#   quantity       — 1 for digital
#   ip_country_code — 2-letter country code (we hardcode 'DE' as a stable default)
#   is_cardable    — "true" if the item supports card checkout (most do)
#   cart_length    — client-side count of items already in cart (informational)
#   fan_id         — main-auth account fan_id
#   ref_token      — OPTIONAL (Phase 0.2 confirmed). When omitted, Bandcamp accepts the add but signals `resync: true`.
#   sync_num       — incrementing per-session counter; out-of-sync values trigger `resync: true` in response
#   req_id         — random float, used by the JS client to correlate response to in-flight request
#   local_id       — random float, client-internal id for the cart entry
#   client_id      — usually empty in body (the real one rides in the `client_id` cookie)
#   Other fields (option_id, discount_id, etc.) are required as keys but accept empty values for plain digital adds.
#
# Cart-DEL form (bonus, captured same session):
#   req=del&id=384754414&client_id=&sync_num=7&req_id=0.6827206053986037
#   `id` is the SERVER-assigned cart-line id (returned in the cart_data after a successful add),
#   NOT the bandcamp item_id. We currently do not need DEL for the mirror, but it's documented
#   here in case the user later wants to undo a bulk cart-add.
